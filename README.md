Overview
This project investigates the replication and extension of LLMEmbed: Rethinking Lightweight LLM's Genuine Function in Text Classification (ACL 2024). It uses representations from LLaMA 2, BERT-large and RoBERTa-large with a downstream classification model, rather than relying on autoregressive label generation.

The notebook covers four research questions:
Research question	Scope
RQ1 — Original replication	SST-2, MR, AG News, Reuters-8 (R8), Reuters-52 (R52)
RQ2 — Cross-domain generalisation	BANKING77, CLINC150, TREC, TweetEval, 20 Newsgroups
RQ3 — Limited-data learning	BANKING77, CLINC150, 20 Newsgroups at 1%, 5%, 10%, 25%, 50%, 100% of training data
RQ4 — Robustness	Controlled perturbations, human review, LLM-based semantic judging and original-versus-modified predictions

Notebook structure
Shared setup
The initial cells install dependencies, clone the original LLMEmbed repository, mount Google Drive, prepare datasets and define encoder, representation-extraction, classifier and evaluation helpers.

Important: The notebook includes more than one version of some setup and RQ1 helper functions because code from separate notebooks was merged. Later definitions can override earlier ones. Avoid executing cells out of order, and check the active definitions and paths before running a section.
RQ1 — Replication of the five original benchmarks
RQ1 prepares the original benchmark datasets, extracts or reuses LLaMA 2 / BERT / RoBERTa representations, and trains a downstream classifier. The retained training workflow uses 100 epochs, batch size 32, learning rate 1e-4, and seed 42. The notebook includes both executable RQ1 code and historical, saved training/evaluation outputs.

The following accuracy values are recorded in the project report and saved RQ1 results:
Dataset	Original paper accuracy	Recorded replicated accuracy
SST-2	95.76%	93.12%
MR	95.49%	95.25%
AG News	95.83%	94.39%
R8	98.22%	97.53%
R52	95.68%	94.98%
Mean	96.20%	95.05%


These are recorded experimental results, not independently re-executed values. Reproducing them requires matching the dataset sources, splits, cached representation settings and downstream training configuration. In particular, the MR evaluation split/count should be audited before claiming exact correspondence with the original paper.
RQ2 — Cross-domain generalisation
The RQ2 section evaluates the framework on BANKING77, CLINC150, TREC, TweetEval and 20 Newsgroups. It uses prepared dataset files and model representations from the shared pipeline. Inspect the saved outputs and checkpoints to determine which results were actually completed; do not interpret printed historical summaries as evidence of a fresh run.
RQ3 — Limited-data classification
RQ3 uses three seeds (42, 123, 2026) and six training fractions across BANKING77, CLINC150 and 20 Newsgroups. The notebook includes checkpoint lookup, training/evaluation, summaries and a TF-IDF baseline. Its configuration includes a RUN_RQ3 switch. Verify the switch and the checkpoint paths before executing, since rerunning all combinations is computationally expensive.
RQ4 — LLMEmbed Robustness Dataset (LRD)
RQ4 builds controlled original/modified text pairs from BANKING77, CLINC150 and 20 Newsgroups, including punctuation changes, minor spelling errors, synonym replacement, word removal, informal rewriting and shortening.

The notebook contains code for candidate generation, automated judging, creation/loading of a human-review CSV, validation, extraction of paired representations, prediction comparisons and robustness/similarity metrics.

Human review is a real manual dependency. The exported review CSV must be completed before the validation and final selection cells can run. The automated judge does not substitute for a human-validated subset. Confirm that the required review and checkpoint files exist before running downstream robustness evaluation.

Reproducibility and known limitations
- Merged notebook: Shared functions and configurations are repeated across sections. Some cells depend on variables or files created earlier; the notebook is not a tested one-click pipeline.
- Historical outputs: Notebook cell outputs were retained from previous executions. Re-execution may produce different results or encounter missing dependencies.
- Model access: LLaMA 2 is gated and requires appropriate Hugging Face access.
- Large caches: Representation extraction can consume significant GPU time and Drive storage; use validated cached tensors when available.
- Evaluation protocol: Dataset sources, split sizes, model revisions and preprocessing must match to support direct comparison with published results. The MR split/count requires particular attention.
- RQ2/RQ3 comparability: The recorded full-data BANKING77 accuracies differ between the two experiments. Their settings must be reconciled before treating them as a controlled comparison.
- RQ4 annotation: Human–LLM agreement is not human–human inter-annotator agreement. Candidate pairs should not be described as validated unless they passed the documented human review.
- Efficiency claims: Recorded downstream classifier training times do not include all representation-extraction costs and should not be presented as end-to-end speedups.
For a reproducibility submission, record the notebook revision, official repository commit, GPU type, package versions, model revisions, dataset versions/splits, random seeds and paths to output files. Execute from a fresh runtime and archive the resulting logs.
